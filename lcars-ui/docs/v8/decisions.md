# v8 decisions — Adaptive Console Scenes

Status: **approved by owner 2026-11-04** (PLAN.md step 0.2.4). Target: spec 0.2.0 at
`~/Documents/Projects/lcars-unification-project/`. Spec decision ids (D01-R2 …) are cited
where a v8 decision implements or narrows one.

| ID | Decision | Implements | Why / boundary |
|---|---|---|---|
| V8-D01 | **Python declares, browser resolves.** Python emits a `SceneModel` (regions, relations, modes, transitions, policy) and validates its topology. The browser compositor measures content and the field, picks a family and produces geometry. Python never sends pixel coordinates for a scene. | D08-R2, IMPLEMENTATION "Boundaries" | Fit depends on fonts, zoom, locale and viewport, which only the browser knows. The Surface Engine resolves anchors in Python against a fixed design size; scenes cannot work that way. |
| V8-D02 | **A family is a parameterised template, not a solver.** Each family is a pure TS function `(slots, field, measurements, tokens) → Candidate \| Infeasible(reason)`. | D11, LAYOUT-GRAMMAR §6 ("authored set … acceptable") | Deterministic, unit-testable, explainable. A general optimiser is explicitly not required. |
| V8-D03 | **Slots are derived from relations.** A mode's `focal` regions fill the focal slot; regions that `controls` a focal region become its attached command bank; `details` → anchored branch; `compares` → fork pair + bridge; `recovers` → reserved alert branch; `part_of` → shared band/enclosure; `feeds` → directed connector. A region may override with an explicit `slot=`. | LAYOUT-GRAMMAR §1, §3 | Authors describe meaning; the geometry follows. Explicit override is the escape hatch. |
| V8-D04 | **Geometry reuses the Surface Engine's path builders** (`surfaceGeometry.ts`: `elbowPath`, `pathFromCommands`, `connectorPath`, arcs) and its SVG-under-DOM layering pattern. A new `SceneRenderer` consumes a `ResolvedScene`; it does not compile to `surface` widgets. | D02-R2, PLAN rule "build on surface()" | Shares the geometry kernel without inheriting Python-side coordinate resolution (V8-D01). |
| V8-D05 | **v8.0 regions have one rectangular safe interior.** The shaped character comes from bands, elbows, junctions and apertures that wrap, branch and step around those interiors. Multi-interior (L-shaped / stepped) region envelopes are deferred to v8.x. | LAYOUT-GRAMMAR §2 (narrowed) | Acceptance's "shaped region" gate is satisfied at the composition level (wrap / fork / contour around measured interiors). Multi-interior content flow is the riskiest part of the spec and isn't needed for the proving workflows. |
| V8-D06 | **Chooser is lexicographic.** 1. Reject candidates failing hard constraints. 2. The mode's preferred family list, in order (e.g. `["fork", "branch", "focus"]`). 3. Continuity tie-break: fewest region moves relative to the current scene. 4. Fallback: `focus` subscene, then offer the access view. | LAYOUT-GRAMMAR §5–6, D11 | No weighted cost function in v8.0. Same inputs → same scene. Every result carries an explanation string. |
| V8-D07 | **Mode changes are server-authoritative.** Handlers call `ctx.set_mode(mode_id, subjects={…})`, which emits a versioned `scene_mode` downstream event. Client-side optimistic transitions are deferred. | D08-R2, D10 | Python owns task state and permissions, so a mode can't be entered that the server didn't approve. Latency is one round trip on an existing WebSocket; acceptable for v8.0. |
| V8-D08 | **Minimum v8.0 modes and families.** Families: `wrap`, `branch`, `fork`, `focus`, `contour`. A mode names its required/optional/focal regions, active relations and preferred families. The proving app exercises overview/inspect (wrap), select (branch), compare (fork), edit (contour or focus) and alert (recovery branch). | LAYOUT-GRAMMAR §3, ACCEPTANCE §4 | Covers all three proving workflows. |
| V8-D09 | **A region is a container widget** (`scene_region`), so its contents are ordinary existing widgets, and streaming `widget_update`s, forms and `WIDGET_CHILD_KEYS` recursion keep working unchanged. | COMPONENTS "Participation in a console scene" | Zero changes to leaf widgets. |
| V8-D10 | **Scene pages own the whole field.** `layout="scene"` implies `chrome="none"`. Page navigation, title, mode and the return path become a built-in **scene context terminal** the families place on a band; there is no mandatory header or sidebar. | LCARS.md §3, COMPONENTS "Scene context" | The rail shell is exactly the website anatomy the spec supersedes. |
| V8-D11 | **Interaction locks live in the frontend.** Focus-within, pointer capture, IME composition and dirty drafts lock a region's identity and placement. Structural commits are deferred while a lock is held, unless the user explicitly requested the change. Defaults follow spec policy: 750 ms quiet window, 5000 ms minimum background interval. | D06-R2, D10, LAYOUT-GRAMMAR §7 | Region DOM nodes are keyed by region id and never remounted by recomposition. |
| V8-D12 | **The access view is generated from the same `SceneModel`.** It's a linear, semantically ordered rendering of every region, command and relation (relations as text). It's offered automatically when no family fits, and can always be toggled. | D03-R2, LCARS.md §7 | Equivalence by construction: there's no second hand-authored layout to drift. |
| V8-D13 | **Additive in v8.0.** `archetype="scene"` is opt-in; `auto` never resolves to a scene until M5 decides otherwise; legacy archetypes and the rail shell are untouched. | PLAN v8 working rules | TrekBoard and existing manifests must render unchanged. |
| V8-D14 | **Keep the library's truth-sampled palette.** Adopt the spec's geometry tokens (24 px band, 48 px elbow outer radius, 4 px rhythm, 44 px targets) as compositor policy, and validate contrast pairs in tests. The spec's proposed palette is not imported. | D09, LCARS.md §6 | The palette is already tuned. The geometry tokens are what the compositor needs. |
| V8-D15 | **Examples use original domains only.** Nothing traces or names a screen from any show; the spec's `evidence/` stays out of the repo. | D07 | IP policy, unchanged. |

## Deferred (explicitly not v8.0)

- Multi-interior shaped regions (V8-D05).
- Client-side optimistic mode transitions (V8-D07).
- Weighted/learned layout cost; any ML in layout.
- Floating windows as a scene family (COMPONENTS "Overlays": optional work mode).
- RTL refit beyond what CSS logical properties give for free. This is tested, but not designed for specially.
